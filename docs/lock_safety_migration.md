# 锁安全迁移文档

本文档记录了P2-2阶段将所有`.lock().unwrap()`替换为`safe_lock`的工作。

## 迁移目标

根据implementation_plan.md的要求：
1. 替换所有 `.lock().unwrap()` 与同类 panic 路径
2. 为锁污染提供恢复策略或可诊断错误

- **恢复策略**：如果无法获取锁，使用默认值（0.0）并记录警告

**替换位置3**：`process_queue`函数中的队列访问

## safe_lock函数特性

`safe_lock`函数提供了以下特性：

1. **自动恢复**：当锁被污染（poisoned）时，自动恢复并获取锁
2. **错误诊断**：返回`LockError`类型，提供详细的错误信息
3. **日志记录**：自动记录警告日志，便于诊断问题
4. **无panic**：所有错误都通过Result返回，不会导致程序崩溃

## 恢复策略

针对不同的使用场景，我们采用了以下恢复策略：

### 统计更新场景
- **策略**：如果无法获取锁，记录错误但继续执行
- **理由**：统计更新是辅助功能，不应该阻塞主要业务流程

### 队列访问场景
- **策略**：如果无法获取锁，记录错误并返回，等待下次处理机会
- **理由**：队列处理是异步的，可以等待下次机会

### 数据读取场景
- **策略**：如果无法获取锁，使用默认值或返回空结果
- **理由**：读取操作应该是非阻塞的，使用默认值比阻塞更安全

### 清理操作场景
- **策略**：如果无法获取锁，记录警告但继续处理其他操作
- **理由**：清理操作可以稍后重试，不应该阻塞主要流程
