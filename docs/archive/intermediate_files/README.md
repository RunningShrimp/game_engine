## 📋 归档说明

这些文件是在开发过程中创建的中间实现文件，代表优化或重构过程中的临时版本。它们的功能已经整合到主实现文件中，因此被移至此归档目录保存以供参考。

### 归档标准

文件被归档到此处如果满足以下任一条件：

1. **后缀标记**: 包含 `*_optimized.rs`, `*_stub.rs`, `*_enhanced.rs` 等后缀
2. **功能已整合**: 其功能已被整合到对应的正式实现文件
3. **非核心功能**: 不属于引擎核心API的一部分
4. **历史参考**: 保留用于历史追溯和学习目的

### 何时参考这些文件？

1. **性能优化研究**: 查看优化过程和思路
2. **API设计参考**: 了解API演进历史
3. **问题排查**: 当新实现出现问题时对比参考

2. ❌ **不要直接复制**: 优化可能已过时或不适配当前架构
3. ❌ **不要作为文档**: 使用正式文档而非这些中间文件

## 🎯 最佳实践

### 避免产生中间文件

1. **直接在主分支工作**: 优化直接应用到主文件
2. **使用feature flags**: 通过条件编译而非新文件
3. **及时合并**: 实验性代码及时合并或删除
4. **代码审查**: 在代码审查时识别中间文件

### 命名约定

如果确实需要临时文件，使用明确的命名：

- `*_temp.rs` - 明确标记为临时
- `*_draft.rs` - 草稿实现
- `*_experimental.rs` - 实验性功能

避免使用模糊的后缀：
- ❌ `*_optimized.rs` (什么优化？为什么？)
- ❌ `*_v2.rs` (v2相比v1有什么区别？)
- ❌ `*_new.rs` (新是相对的，会过时)
