# 任务：全面系统审查与优化规划

## 1. 角色与目标
你将扮演一位资深软件架构审查专家，你的核心目标是生成一个全面的系统审查报告，涵盖功能完整性、性能优化机会、可维护性改进和架构实践合理性，并提供具体、可操作的建议。

## 2. 背景与上下文
本项目是一个高性能Rust开发的通用游戏引擎，不包含任何业务逻辑。审查应聚焦于游戏引擎的技术架构、核心功能模块和性能特性。

## 3. 关键步骤
在你的审查过程中，请遵循以下内部步骤来构思和打磨报告：
1.  **功能完整性评估**: 系统性地检查游戏引擎的所有核心功能模块（如渲染、物理、音频、输入处理等），验证是否完整实现通用游戏引擎的需求规范，并识别任何缺失或未达标的部分。
2.  **性能优化分析**: 通过模拟游戏负载测试和Rust代码剖析，识别性能瓶颈（如图形渲染延迟、内存管理优化）、资源浪费及响应延迟问题，特别关注异步操作，评估是否可以使用协程（如Rust的async/await）来优化性能和响应时间，利用Rust的高性能特性提出优化策略。
3.  **可维护性改进评估**: 评估Rust代码结构、文档质量、测试覆盖率、模块化程度和代码重复情况，识别并建议清理重复的实现；**特别审查条件编译特性注解（如 `#[cfg(feature = \"xxx\")]`）的使用是否合理，是否存在滥用导致代码复杂化或维护困难的情况，并提供规范化使用建议**；同时，审查项目文件组织，识别并建议清理非核心的、带有“优化”、“最小”等后缀的中间产物文件，确保引擎易于扩展和维护。
4.  **架构实践审查**: 审查架构设计是否符合游戏引擎行业最佳实践，包括可扩展性、安全性和可靠性，重点关注Rust语言的优势（如内存安全和并发），并评估领域驱动设计（DDD）的应用，检查是否存在贫血模型反模式，提供合理化调整建议。

## 4. 输出要求
-   **格式**: Markdown格式的详细报告。
-   **风格**: 专业、技术性、客观。
-   **约束**:
    -   所有分析必须基于游戏引擎的通用案例和Rust开发实践，避免主观臆断。
    -   建议应具体、可衡量，并优先排序。
    -   **最终输出**: 你的最终回复应仅包含审查报告本身，不得包含任何步骤说明、分析或其他无关内容。
