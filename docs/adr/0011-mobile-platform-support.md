# ADR-0011: 移动平台支持策略

## 状态

已接受

## 日期

2025-01-27

## 背景

游戏引擎需要支持移动平台（iOS和Android），但移动平台有特殊的限制和需求：
- 性能限制
- 功耗限制
- 触摸输入
- 传感器支持
- 平台特定的构建流程

## 决策

实现完整的移动平台支持，包括：

1. **构建支持**
   - iOS构建脚本（`build_ios.sh`）
   - Android构建脚本（`build_android.sh`）
   - 支持多种架构和API级别

2. **平台优化**
   - 自适应性能管理
   - 功耗优化
   - 热节流检测
   - 动态分辨率

3. **输入支持**
   - 触摸输入处理
   - 陀螺仪支持
   - 加速度计支持

4. **配置系统**
   - 移动平台特定配置
   - 从硬件信息自动配置

## 后果

### 正面影响

- **平台覆盖**: 支持iOS和Android平台
- **性能优化**: 自动优化移动平台性能
- **用户体验**: 支持触摸和传感器输入
- **开发效率**: 提供构建脚本简化开发

### 负面影响

- **维护成本**: 需要维护多个平台的代码
- **测试成本**: 需要在多个平台上测试
- **复杂性**: 增加了系统的复杂性

### 限制

- iOS构建只能在macOS上进行
- Android构建需要Android NDK
- 某些功能可能在不同平台上表现不同

## 替代方案

1. **不提供移动平台支持**: 只支持桌面平台
   - 优点：简单
   - 缺点：限制了使用场景

2. **使用第三方框架**: 使用Unity、Unreal等
   - 优点：功能完整
   - 缺点：失去控制权

3. **当前方案**: 原生支持移动平台
   - 优点：完全控制、性能好
   - 缺点：需要更多工作
