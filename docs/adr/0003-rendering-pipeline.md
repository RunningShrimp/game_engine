# ADR-0003: 渲染管线设计

## 状态
已接受

## 日期
2025-01-23

## 背景

渲染管线是游戏引擎的核心组件，需要支持多种渲染技术以适应不同的游戏类型和性能需求：

1. **多种渲染需求**：需要支持 PBR、前向渲染、延迟渲染等多种技术
2. **跨平台支持**：需要支持不同的图形 API (Vulkan, DirectX, Metal, WebGL)
3. **性能优化**：需要 GPU 驱动渲染、实例批处理等技术
4. **资源管理**：需要高效管理纹理、着色器、网格等资源

## 决策

采用 **GPU 驱动渲染** 和 **可扩展渲染管线** 架构。

### 渲染管线架构

- **GPU 驱动渲染**：使用计算着色器进行视锥剔除，减少 CPU-GPU 同步
- **间接绘制**：使用 `DrawIndirect` 命令减少驱动程序开销
- **实例批处理**：合并相同材质的绘制调用
- **LOD 系统**：基于距离的多级细节切换
- **遮挡剔除**：层次化 Z-Buffer (Hi-Z) 剔除

### 技术选型

选择 **WGPU** 作为图形 API 抽象层，原因：
- 跨平台支持 (Vulkan, Metal, DirectX 12, WebGPU)
- 现代 GPU API 设计
- 活跃的社区和文档

## 后果

### 正面影响

1. **性能提升**：GPU 驱动渲染预计提升 30-50% 性能
2. **可扩展性**：模块化设计允许轻松添加新的渲染技术
3. **跨平台**：WGPU 支持主流平台
4. **现代特性**：支持光线追踪、计算着色器等现代 GPU 特性

### 负面影响

1. **复杂性**：渲染管线代码复杂，需要深入理解 GPU 架构
2. **调试难度**：GPU 代码调试比 CPU 代码更困难
3. **硬件依赖**：某些高级特性需要特定硬件支持

## 替代方案

### 方案 A：CPU 驱动渲染
- **优点**：实现简单，易于调试
- **缺点**：性能受限，无法充分利用 GPU
- **未被选择的原因**：无法满足现代游戏引擎的性能需求

### 方案 B：单一渲染技术
- **优点**：实现简单，代码量少
- **缺点**：缺乏灵活性，无法适应不同游戏类型
- **未被选择的原因**：限制了引擎的适用范围
