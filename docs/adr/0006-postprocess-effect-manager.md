# ADR-0006: 后处理效果管理器设计

## 状态
已接受

## 日期
2025-01-27

## 背景

后处理效果系统需要支持：
1. **动态效果链**: 运行时添加/移除效果，适应不同场景需求
2. **性能优化**: 自动优化效果链，减少GPU开销
3. **自适应质量**: 根据性能自动调整质量，保持稳定帧率
4. **预设管理**: 保存和加载常用效果配置
5. **性能监控**: 跟踪每个效果的GPU时间，识别性能瓶颈

现有的 `PostProcessPipeline` 提供固定效果链，但缺乏动态管理和优化能力。

## 决策

采用 **双模式后处理系统** 架构：

### 1. PostProcessPipeline（固定效果链）
- 简单易用，适合固定效果配置
- 性能开销小，无运行时管理开销
- 适合大多数场景

### 2. PostProcessEffectManager（动态效果链）
- 运行时动态管理效果链
- 自动优化和合并兼容效果
- 自适应质量调整
- 预设管理和性能监控

### 架构设计

```
PostProcessEffectManager
├── PostProcessPipeline (基础管线)
├── effect_chain (效果链，按优先级排序)
├── performance_stats (性能统计)
├── quality_mode (质量模式)
└── presets (效果预设)
```

### 效果优先级系统

效果按执行顺序自动排序：
- **Early**: SSAO（深度相关）
- **Mid**: Bloom, Motion Blur, Depth of Field（光照和模糊）
- **Late**: Color Correction（色彩调整）
- **Final**: Tonemap, Antialiasing（输出格式转换）

### 自适应质量系统

根据目标帧时间和实际性能自动调整：
1. 监控总GPU时间
2. 超过目标时降低质量模式
3. 仍超时则禁用最耗时的效果
4. 性能恢复时逐步提高质量

## 后果

### 正面影响

1. **灵活性**: 运行时动态管理效果，适应不同场景
2. **性能**: 自动优化效果链，减少GPU开销
3. **用户体验**: 自适应质量保持稳定帧率
4. **开发效率**: 预设系统简化配置管理
5. **可观测性**: 性能监控帮助识别瓶颈

### 负面影响

1. **复杂性**: 增加了系统复杂度
2. **内存开销**: 需要存储效果链和性能统计
3. **CPU开销**: 运行时优化和监控需要CPU时间

## 替代方案

### 方案 A：仅使用固定效果链
- **优点**: 实现简单，性能开销小
- **缺点**: 缺乏灵活性，无法适应动态需求
- **未被选择的原因**: 无法满足现代游戏的动态需求

### 方案 B：完全动态系统，移除固定管线
- **优点**: 统一接口，简化API
- **缺点**: 简单场景也需要动态管理开销
- **未被选择的原因**: 固定管线对简单场景更高效

## 实现细节

### 效果合并

兼容的效果可以合并：
- 多个 `ColorCorrection` 合并为一个
- 多个 `Tonemap` 合并为一个（保留最后一个）

### 质量模式调整

质量模式自动调整效果参数：
- **Low**: 降低模糊半径、采样数，可能禁用SSAO
- **Medium**: 默认平衡设置
- **High**: 增加模糊半径、采样数
- **Ultra**: 最大质量设置（用于截图）

### 性能监控

每个效果跟踪：
- 平均GPU时间
- 最大GPU时间
- 调用次数
- 启用状态
