# ADR-0005: 使用 Rust 语言

## 状态
已接受

## 日期
2025-01-23

## 背景

游戏引擎需要一种能够满足以下需求的编程语言：

1. **性能**：游戏引擎需要极高的性能，能够充分利用硬件资源
2. **内存安全**：内存管理错误（如空指针、缓冲区溢出）是游戏开发中的常见问题
3. **并发安全**：现代游戏引擎需要充分利用多核 CPU 进行并发处理
4. **跨平台支持**：需要支持主流平台（Windows、macOS、Linux、Web）
5. **生态系统**：需要丰富的库和工具支持

## 决策

选择 **Rust** 作为游戏引擎的主要编程语言。

### Rust 的优势

#### 性能
- 零成本抽象：没有垃圾收集器，没有运行时开销
- 内存控制：精确控制内存分配和释放
- 优化友好的编译器：LLVM 后端提供优秀的优化

#### 内存安全
- 编译时检查：所有权系统在编译时防止内存错误
- 无数据竞争：借用检查器确保线程安全
- 安全的并发：编译器强制执行并发安全规则

#### 并发
- fearless concurrency：Rust 的类型系统确保并发代码的正确性
- 内置并发原语：通道、互斥锁、原子操作等
- 无需 GC：没有垃圾收集器的并发开销

#### 生态系统
- **WGPU**：现代图形 API 抽象，支持 Vulkan、Metal、DX12、WebGPU
- **Bevy ECS**：高性能的 ECS 框架
- **Tokio**：异步运行时，适用于网络和 I/O
- **Rapier**：物理引擎，支持 2D 和 3D

### 与其他语言的比较

| 特性 | Rust | C++ | Go | C# |
|-------|-------|------|-----|-----|
| 内存安全 | ✅ | ❌ | ✅ | ✅ |
| 性能 | ✅ | ✅ | ⚠️ | ⚠️ |
| 并发安全 | ✅ | ❌ | ✅ | ✅ |
| 学习曲线 | ⚠️ | ❌ | ✅ | ✅ |
| 生态系统 | ⚠️ | ✅ | ⚠️ | ✅ |
| 跨平台 | ✅ | ✅ | ✅ | ⚠️ |

## 后果

### 正面影响

1. **内存安全**：编译时防止大多数内存错误
2. **高并发性能**：安全的并发编程模型
3. **无运行时开销**：没有 GC，没有 VM
4. **现代工具链**：Cargo 包管理器，优秀的 IDE 支持
5. **跨平台编译**：可以编译到 WebAssembly、移动平台等

### 负面影响

1. **学习曲线**：Rust 的所有权和借用系统需要学习
2. **编译时间**：Rust 编译时间较长
3. **生态系统成熟度**：某些领域的库比 C++ 少
4. **互操作性**：与 C/C++ 库的互操作需要 FFI

## 替代方案

### 方案 A：使用 C++
- **优点**：生态系统成熟，性能极高，行业标准
- **缺点**：内存不安全，并发编程困难
- **未被选择的原因**：内存安全是现代游戏引擎的关键需求

### 方案 C：使用 Go
- **优点**：并发简单，学习曲线平缓
- **缺点**：GC 开销，性能不如 Rust/C++，图形 API 支持有限
- **未被选择的原因**：性能不足，GC 不适合实时游戏

### 方案 D：使用 C#
- **优点**：语言友好，生态系统完善
- **缺点**：依赖 .NET 运行时，性能不如 Rust/C++，跨平台支持有限
- **未被选择的原因**：运行时开销，不适合高性能游戏引擎
