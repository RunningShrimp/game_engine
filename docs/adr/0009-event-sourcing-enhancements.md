# ADR-0009: 事件溯源增强功能设计

## 状态

已接受

## 日期

2025-01-27

## 背景

基础的事件溯源系统已经实现，但缺少高级功能，如：
- 复杂的事件查询
- 时间旅行调试
- 事件统计和分析
- 事件流处理

这些功能对于调试、分析和监控系统状态非常重要。

## 决策

实现增强的事件溯源系统（`event_sourcing_enhanced`），提供：

1. **事件查询系统**（`EventQuery`）
   - 支持按聚合ID、事件类型、时间范围、版本范围查询
   - 支持分页和排序

2. **时间旅行调试**
   - 重放到指定时间点
   - 重放到指定版本

3. **事件统计**
   - 按类型统计
   - 按聚合统计
   - 时间范围分析

4. **事件流处理**
   - 过滤器
   - 转换器
   - 批量处理

5. **事件投影框架**
   - 从事件流构建只读视图
   - 支持投影状态序列化

## 后果

### 正面影响

- **调试能力增强**: 可以轻松重放到任意时间点进行调试
- **分析能力增强**: 可以查询和分析事件历史
- **监控能力增强**: 可以统计和分析事件模式
- **灵活性**: 事件流处理提供了强大的数据转换能力

### 负面影响

- **性能开销**: 查询和统计需要遍历事件列表
- **内存使用**: 事件历史会占用内存
- **复杂性**: 增加了系统的复杂性

### 限制

- 由于`EventSourcingManager`的`event_store`字段是私有的，部分功能（如全局事件查询）需要聚合ID
- 这是设计上的限制，确保事件溯源在聚合边界内工作

## 替代方案

1. **直接访问event_store**: 将`event_store`字段改为公共
   - 优点：功能更完整
   - 缺点：破坏封装性

2. **在EventSourcingManager中添加公共方法**: 添加查询和统计方法
   - 优点：保持封装性
   - 缺点：需要修改基础类

3. **当前方案**: 通过公共API访问，简化部分功能
   - 优点：不破坏现有设计
   - 缺点：功能有限制
