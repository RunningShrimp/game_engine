# API 稳定性矩阵 (API Stability Matrix)

本文档记录游戏引擎中各个 API 的稳定性状态，帮助开发者了解哪些 API 可以安全使用，哪些可能会发生变化。

## 稳定性级别定义

| 级别 | 说明 | 破坏性变更预期 |
|------|------|----------------|
| **Stable** (稳定) | 经过充分测试，API 设计成熟 | 极少，仅在重大版本更新时 |
| **Mature** (成熟) | 功能完整，少量优化可能 | 偶尔，有明确迁移路径 |
| **Experimental** (实验性) | 功能开发中，API 可能变化 | 频繁，可能无迁移路径 |
| **Deprecated** (已弃用) | 计划移除，建议替代方案 | 即将移除 |

## 使用实验性 API 的注意事项

### 1. 版本锁定
实验性 API 可能会在小版本更新中发生变化。建议在 `Cargo.toml` 中锁定版本：

```toml
[dependencies]
game_engine = "=0.1.0"  # 锁定特定版本
```

### 2. 定期检查更新
关注 CHANGELOG.md 和本文档，了解 API 变更：

```bash
# 查看变更日志
cat docs/CHANGELOG.md

# 查看当前状态
cat docs/API_STABILITY.md
```

### 3. 提供反馈
如果在实验性 API 中发现问题或有改进建议，请：
- 创建 GitHub Issue
- 标记为 `experimental-api` 标签
- 描述使用场景和期望行为

### 4. 准备迁移
实验性 API 变更时，我们尽量提供：
- 变更说明
- 迁移指南
- 废弃警告（编译器警告）

## API 稳定性评估标准

### 从实验性升级到稳定的标准

1. **功能完整性**: 核心功能全部实现且测试充分
2. **性能表现**: 达到预期的性能目标
3. **用户反馈**: 至少 3 个项目成功使用且反馈良好
4. **文档完整**: 包括使用指南、示例和最佳实践
5. **测试覆盖**: 单元测试覆盖率 > 80%
6. **代码审查**: 通过核心团队审查
7. **稳定性验证**: 在 beta 版本中至少 2 个月无重大问题
