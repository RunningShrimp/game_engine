# 性能监控仪表板 - 快速使用指南

## 快速开始

### 打开仪表板
在游戏引擎编辑器中，有两种方式打开性能监控仪表板：

1. **键盘快捷键**: 按下 `F12` 键
2. **菜单按钮**: 点击底部状态栏右侧的 "📊 Performance" 按钮

## 功能说明

### 左侧面板 - 实时指标

显示当前帧的核心性能指标：

- **FPS (帧率)**: 每秒帧数
  - 🟢 绿色: >55 FPS (流畅)
  - 🟡 黄色: 30-55 FPS (可接受)
  - 🔴 红色: <30 FPS (卡顿)

- **Frame Time (帧时间)**: 每帧渲染耗时
  - 目标: <16.67ms (60 FPS)
  - 警告: >20ms
  - 严重: >33ms

- **CPU/GPU/Memory 使用率**
  - 进度条可视化
  - 百分比显示
  - 总容量参考

- **渲染统计**
  - Draw Calls: 绘制调用次数
  - Triangles: 三角形数量

- **物理统计**
  - 物理计算耗时
  - 刚体数量
  - 碰撞检测次数

- **脚本统计**
  - 脚本执行耗时
  - 活动脚本数量

### 中间面板 - 性能图表

#### 1. FPS曲线图
显示最近60秒的帧率变化
- 蓝线: 实际FPS
- 绿线: 60 FPS目标线
- 顶部显示: 最小/平均/最大FPS

#### 2. 系统使用率饼图
显示各系统占用比例
- 🎨 蓝色: 渲染系统
- ⚡ 红色: 物理系统
- 📜 绿色: 脚本系统
- 🔊 橙色: 音频系统
- 🌐 紫色: 网络系统
- 📦 灰色: 其他

#### 3. 内存趋势图
显示内存使用随时间变化
- 紫色面积: 当前内存使用
- 虚线: 平均内存使用
- ⚠️ 自动检测内存泄漏

### 右侧面板 - 性能热点

显示当前帧中耗时最多的系统（Top 5）：

1. **排行编号**: 1-5
2. **系统名称**: 例如 "PhysicsSystem::update"
3. **耗时**: 例如 "8.5 ms"
4. **占比**: 例如 "53%"
5. **调用次数**: 例如 "60 calls"
6. **进度条**: 可视化占比

**交互**: 点击任一热点，弹出详细信息窗口

### 视图切换

顶部标签页切换不同视图：

#### 实时 (Realtime)
- 显示实时性能数据
- 自动更新
- 可调更新频率

#### 历史 (History)
- 查看历史数据
- 时间范围选择（开发中）

#### 告警 (Alerts)
- 查看所有告警
- 确认/清除告警
- 筛选未确认告警

## 告警系统

### 告警类型

#### 严重告警 (🔴)
会触发顶部闪烁横幅：
- FPS < 30
- 内存 > 95%
- GPU > 95%
- 帧时间 > 33ms
- CPU > 95%

#### 警告告警 (🟡)
仅在列表中显示：
- FPS < 50
- 内存 > 85%
- GPU > 85%
- 帧时间 > 20ms
- CPU > 85%

### 告警操作

1. **确认告警**: 点击 "Acknowledge" 按钮
   - 标记为已确认
   - 半透明显示

2. **清除所有**: 点击右上角 "Clear All"
   - 删除所有告警

3. **筛选**: 下拉菜单选择
   - "All": 显示全部
   - "Unacknowledged": 仅显示未确认

## 配置选项

### 更新频率
在实时视图右上角：
- **100ms**: 最实时，较高CPU开销
- **250ms**: 推荐（默认）
- **500ms**: 平衡模式
- **1s**: 低开销

### 关闭仪表板
- 按 `F12` 键
- 或点击右上角 `×` 按钮

## 使用技巧

### 1. 性能优化工作流

```
1. 打开性能仪表板
2. 运行游戏场景
3. 观察FPS和热点面板
4. 找到耗时最高的系统
5. 点击查看详细信息
6. 优化代码
7. 重新测试验证
```

### 2. 内存泄漏检测

1. 观察内存趋势图
2. 如果内存持续增长 → 显示黄色警告 "Possible Memory Leak"
3. 点击热点查看内存分配
4. 检查对象生命周期管理

### 3. 帧时间优化

目标帧时间：
- 60 FPS: 16.67ms
- 30 FPS: 33.33ms

如果超出：
1. 查看热点面板
2. 优化Top 3耗时系统
3. 减少Draw Calls
4. 优化物理计算

### 4. 批量测试

使用导出功能（开发中）：
1. 记录基线性能
2. 修改代码
3. 对比性能变化
4. 确保无性能回归

## 常见问题

### Q: 为什么显示的FPS和实际感觉不同？
A: FPS显示的是编辑器渲染帧率，游戏运行时可能不同。需要在游戏运行时观察。

### Q: 内存泄漏检测准确吗？
A: 是基于趋势的启发式检测，如果后半段平均内存比前半段高20%，会发出警告。

### Q: 如何减小性能影响？
A: 将更新频率调至1s，或关闭仪表板。

### Q: 历史数据保存在哪里？
A: 目前在内存中，关闭编辑器会丢失。导出功能开发中。

## 最佳实践

1. **开发阶段**: 设置更新频率为250ms，实时监控
2. **性能测试**: 设置更新频率为100ms，精确测量
3. **长期运行**: 设置更新频率为1s，降低开销
4. **发布前**: 导出性能报告，确保符合要求
